
셋 다 "정적 사이트 올릴 때 쓰는 것"으로 뭉뚱그려 알고 있었는데, **층위가 다르다.**

이런 개념인 듯
```
Amplify      ← 위 두 개를 묶어주는 도구 (빌드 + 배포 + 도메인)
  ├ CloudFront ← 전 세계에 뿌리고 캐싱 (전달)
  └ S3         ← 파일이 실제로 있는 곳 (저장)
```

---

## S3 — 저장소

파일을 넣어두는 곳. 서버가 아니라 **버킷**이라는 저장 공간이다.

- 용량 걱정이 없고, 넣어둔 만큼만 돈을 낸다
- 정적 웹 호스팅 기능이 있어서 HTML을 올리면 URL로 열린다
- 다만 **파일이 있는 리전에서만** 서빙된다 → 서울 버킷이면 미국 사용자는 느리다
- HTTPS 커스텀 도메인을 S3만으로는 못 붙인다

## CloudFront — CDN

S3 앞에 세워두는 **전 세계 캐시 서버망**이다.

- 사용자와 가까운 엣지에서 응답 → 지연시간이 줄어든다
- 캐시가 있으면 S3까지 안 간다 → S3 요청 비용도 줄어든다
- **HTTPS와 커스텀 도메인이 여기서 해결된다**
- 캐시가 남아 있으면 새로 배포해도 옛날 파일이 나온다 → 무효화(invalidation) 필요

> S3만 쓰면 원본 하나, CloudFront를 붙이면 전 세계에 사본이 생긴다.

## Amplify — 묶음 도구

위 둘을 직접 세팅하는 대신, **Git 연동부터 배포까지 자동으로** 해준다.

- GitHub에 push → 자동 빌드 → 자동 배포
- 내부적으로 S3 + CloudFront를 쓴다. 직접 만질 필요가 없어질 뿐
- PR마다 미리보기 환경을 만들어준다
- 인증, API, 백엔드 기능도 붙일 수 있다

대신 **세밀한 제어를 포기한다.** 캐시 정책이나 라우팅을 깊게 손대려면 결국 S3 + CloudFront를 직접 구성하게 된다고 하는데 claude 너만 믿는다.

---

## 한 줄로

> **S3는 창고, CloudFront는 전국 물류망, Amplify는 그 둘을 대신 계약해주는 대행사.**
