
> 오늘의 핵심 질문: **"끌 것만 끄면 되지, 왜 살아남은 값까지 키우지?"** 답: 키우는 게 목적이 아니다. 학습과 추론의 스케일을 맞추는 게 목적이고, 키우기는 그 수단 중 하나일 뿐이다.

## 1. Dropout은 왜 뉴런을 끄는가 — 공동적응(Co-adaptation)

보정 얘기를 하기 전에, 애초에 왜 끄는지부터.

이상적으로는 뉴런마다 서로 다른 특징을 잡아야 한다. 동물 분류라면 하나는 귀 모양, 하나는 꼬리, 하나는 털색을 감지하는 식으로. 그런데 실제로는 **여러 뉴런이 비슷한 특징을 중복 학습하고, 각자의 가중치가 다른 뉴런의 출력에 의존하게 되는** 현상이 생긴다. 이것이 **공동적응**이다.

쉽게 말하면 **뉴런들이 서로 눈치를 보며 조를 짜버리는 것**이다.

> "쟤가 이 값을 내주니까 나는 거기 맞춰서 보정만 하면 돼"

팀 프로젝트에서 몇 명이 붙어 다니며 서로에게만 의존하는 상황과 같다. 훈련 데이터에서는 이 조합이 잘 먹히지만, 새 데이터에서 한 명이 삐끗하면 조 전체가 무너진다. 이게 오버피팅으로 이어진다.

Dropout은 **매 스텝마다 랜덤으로 조원을 빼버려서** 이걸 막는다. 누가 사라질지 모르니 각자 혼자서도 쓸모 있는 특징을 학습하게 된다.

### 앙상블 관점

뉴런이 n개면 켜고 끄는 조합이 이론상 2^n가지다. 그래서 dropout을 **하나의 네트워크 안에서 수많은 서브네트워크를 훈련시키는 앙상블**로 해석하기도 한다. 랜덤포레스트가 트리 여러 개의 평균을 내는 것과 비슷한 그림이다.

단, 이건 **엄밀한 증명이라기보다 직관적 해석**이다. 서브네트워크들이 가중치를 공유하므로 독립 앙상블과는 다르고, 추론 결과가 진짜 앙상블 평균과 일치하는 건 선형 모델에서나 성립한다. "그렇게 이해하면 감이 잡힌다" 정도로 받아들일 것.

**정리: 끄는 것은 공동적응을 깨기 위한 목적, 아래의 `1/(1-p)`는 그 부작용을 수습하는 뒤처리.** 목적과 뒤처리를 구분해서 보면 깔끔하다.

## 2. Dropout의 스케일 보정

### 2.1 왜 끄는 것만으로는 부족한가

"끌 것만 끄면 되지 않나"가 자연스러운 직관이다. 하지만 다음 층 입장에서 보면 이야기가 달라진다. 다음 층은 개별 뉴런을 하나씩 보는 게 아니라 **가중합**을 본다.

```
z = w1*x1 + w2*x2 + ... + w100*x100
```

뉴런 100개가 각각 1.0이고 가중치가 0.1이라면 `z = 10`이다. 여기서 절반을 끄면 **항 자체가 50개 사라지므로** `z ≈ 5`가 된다. 끈 뉴런만 0이 되고 끝나는 게 아니라, **합계가 통째로 절반이 되는 것**이 문제의 본질이다.

그래서 이런 일이 벌어진다.

- **학습 중**: 계속 `z ≈ 5`를 보면서 "이 정도 크기가 정상"이라고 학습함
- **추론 시**: dropout을 끄니 `z = 10`이 들어옴

학습 내내 5 근처만 보던 모델에게 갑자기 10을 주는 셈이다. 활성화 함수는 비선형이므로 5와 10은 전혀 다른 출력을 내고, 층을 거칠수록 이 어긋남이 증폭된다.

### 2.2 왜 하필 `1/(1-p)` 배인가

통계 문제로 보면 깔끔하다. **일부만 샘플링해놓고 전체 합을 추정하는 상황**이다.

> 100명이 내는 회비 총액을 알고 싶은데 50명만 냈다면, 총액 추정치는 `(50명이 낸 금액) × 2`다.

Dropout도 똑같다. 전체 뉴런 중 `(1-p)` 비율만 살아남았으니, 전부 켜져 있었다면 나왔을 값을 추정하려면 `1/(1-p)`를 곱해야 기댓값이 맞는다.

```
mask ~ Bernoulli(1-p)
y = (x * mask) / (1-p)

E[y] = (1-p) * x/(1-p) = x    # 기댓값이 원본과 같아진다
```

즉 `/(1-p)`는 **"전부 켜져 있었다면 나왔을 값"의 불편 추정량을 만드는 보정 계수**다.

### 2.3 사실 키울 필요도 없다

여기가 핵심이다. 맞춰야 하는 건 **학습과 추론의 상대적 스케일**이지 절대값이 아니다. 그래서 반대 방향으로 해도 똑같이 성립한다.

||학습 시 z|추론 시 z|맞나?|
|---|---|---|---|
|보정 없음|5|10|❌|
|**학습 때 2배** (Inverted Dropout)|10|10|✅|
|**추론 때 0.5배** (원논문 방식)|5|5|✅|

원논문은 실제로 아래쪽 방식이었다. 추론할 때 가중치에 `(1-p)`를 곱해 값을 **줄이는** 방식이고, 결과는 동일하게 잘 동작한다.

그런데도 지금 다들 "키우는" 쪽(Inverted Dropout)을 쓰는 이유는 순전히 실무적이다. 보정을 학습 쪽에 몰아넣으면 **추론 코드에 손댈 것이 하나도 없기 때문**이다. `eval()` 모드에서 dropout 계층은 입력을 그대로 반환하기만 하면 된다. 학습은 한 번이고 추론은 수백만 번 돌아가니 합리적인 트레이드오프다. PyTorch `nn.Dropout`도 이 방식이다.

**"왜 키우냐"의 답은 "키워야만 해서"가 아니라, "어차피 맞춰야 하는 걸 추론 대신 학습 쪽에서 맞추기로 해서"이다.**

### 2.4 직접 확인

```python
import torch
import torch.nn as nn

d = nn.Dropout(p=0.5)
x = torch.ones(10000)

d.train()
print(d(x).mean())   # ≈ 1.0  (값은 0 아니면 2.0, 평균은 유지)
print(d(x).unique()) # tensor([0., 2.])  ← 1/(1-p) = 2배로 키운 흔적

d.eval()
print(d(x).mean())   # 1.0  (아무 처리 없이 그대로 통과)
```

### 2.5 함정 세 가지

**(1) 보정되는 건 기댓값뿐, 분산은 아니다.** `E[y] = x`는 맞췄지만 `Var[y]`는 학습과 추론이 다르다. 그래서 Dropout과 BatchNorm을 연달아 쓰면 BN이 누적한 running variance가 추론 시 실제 분산과 어긋나 성능이 떨어질 수 있다 (variance shift).

**(2) `model.eval()`을 빼먹으면 추론 때도 dropout이 켜져 있다.** 결과가 호출할 때마다 달라지는데 에러는 안 난다. 조용히 틀리는 종류의 버그라 더 위험하다.

**(3) 마스크는 미니배치 단위가 아니라 샘플 단위로 생성된다.** "미니배치마다 뉴런을 끈다"는 설명을 종종 보는데, PyTorch 구현은 **배치 안의 샘플마다 마스크가 따로** 만들어진다. 같은 배치의 1번 샘플과 2번 샘플이 서로 다른 뉴런을 끈다. 마스크 shape을 직접 다룰 때 헷갈리기 쉬운 지점.

### 2.6 비율(p) 설정

고전적인 권장값은 입력층/출력층 0.2 내외, 은닉층 0.5 내외다. 다만 이건 2012년 CNN/MLP 시절의 관행이고, **요즘 Transformer 계열은 0.1을 훨씬 많이 쓴다.** 모델이 크고 데이터가 많으면 강한 dropout이 오히려 학습을 방해한다. 숫자를 외우기보다 "층 위치와 모델 규모에 따라 다르다"로 기억할 것.

## 3. BatchNorm

### 3.1 무엇을 하나

**배치 방향으로** 정규화한다. 입력이 `(N, C)`라면 각 채널 `C`마다 배치 `N`개를 모아 평균/분산을 계산한다.

```
x̂ = (x - μ_B) / sqrt(σ²_B + ε)
y = γ * x̂ + β
```

`ε`은 0으로 나누는 것을 막는 안전장치.

### 3.2 γ, β가 있는 이유

정규화는 분포를 평균 0, 분산 1로 강제하는데 이는 표현력을 깎는 행위다. `γ`(scale)와 `β`(shift)는 **학습되는 파라미터**로, 모델이 필요하다고 판단하면 정규화를 되돌릴 수 있는 자유도를 남겨둔다. 극단적으로 `γ=σ, β=μ`면 원래 값으로 복원된다.

### 3.3 학습과 추론의 동작이 다르다

- **학습**: 현재 배치의 통계(`μ_B`, `σ²_B`)를 사용 + running mean/var를 EMA로 누적
- **추론**: 누적해둔 running 통계를 사용 → 배치 구성과 무관하게 결정적인 출력

Dropout과 마찬가지로 `train()` / `eval()` 전환이 필수다.

### 3.4 한계

- 배치가 작으면 통계가 불안정하다. 배치 1이면 분산이 0이라 사실상 못 쓴다.
- 길이가 가변인 시퀀스 데이터에 잘 맞지 않는다. 패딩 위치까지 통계에 섞인다.
- 학습 시 배치 내 다른 샘플에 출력이 의존한다 (샘플 간 독립성 깨짐).

---

## 4. LayerNorm

`LinearNorm`이라는 이름은 없다. **LayerNorm**이 맞는 이름.

### 4.1 무엇을 하나

**샘플 하나 안에서 feature 방향으로** 정규화한다. 입력이 `(N, L, D)`라면 각 `(n, l)` 위치마다 `D`개 feature로 평균/분산을 낸다. **옆 샘플을 전혀 보지 않는다.**

수식 자체는 BatchNorm과 같다. 다른 건 오직 **어느 축으로 평균을 내느냐**다.

### 4.2 그래서 좋은 점

- 배치 크기 1이어도 동작한다
- running 통계가 없다 → **학습과 추론 동작이 완전히 동일**
- 시퀀스 길이가 달라도 문제없다

Transformer가 LayerNorm을 쓰는 이유가 정확히 이것이다. 가변 길이 시퀀스 + 작은 배치 환경에서 BatchNorm은 답이 없다.

---

## 5. 한눈에 비교

||BatchNorm|LayerNorm|
|---|---|---|
|정규화 축|배치 (샘플 **간**)|feature (샘플 **내**)|
|배치 크기 의존|있음|없음|
|train/eval 동작|다름 (running stat)|같음|
|running 버퍼|있음|없음|
|가변 길이 시퀀스|부적합|적합|
|주 사용처|CNN / 비전|Transformer, RNN|

한 줄 요약: **BN은 세로로 자르고, LN은 가로로 자른다.**

## 6. 덧 — RMSNorm

요즘 LLM(LLaMA 계열 등)은 LayerNorm 대신 **RMSNorm**을 쓴다.

```
LayerNorm:  (x - mean) / sqrt(var + ε) * γ + β
RMSNorm:    x / sqrt(mean(x²) + ε) * γ
```

평균을 빼는 단계(re-centering)를 생략하고 RMS로 나누기만 한다. 성능은 비슷한데 연산이 줄어든다. LayerNorm의 효과 대부분이 re-centering이 아니라 re-scaling에서 온다는 관찰에 기반한다.

## 7. Dropout의 변형들 — 이름만 걸어두기

- **DropConnect**: 뉴런 대신 개별 연결(가중치)을 제거
- **Gaussian Dropout**: 완전히 끄는 대신 출력에 가우시안 노이즈를 더함
- **Spatial Dropout**: CNN에서 채널 단위로 적용
- **Curriculum Dropout**: 학습이 진행됨에 따라 비율을 점차 낮춤
- **Monte Carlo Dropout**: 추론 때도 dropout을 켜고 여러 번 돌려, 결과의 분산으로 예측 불확실성을 측정

이 중 **MC Dropout**만 기억해두면 좋다. 위에서 "eval()을 안 부르면 결과가 매번 달라진다"를 버그로 다뤘는데, MC Dropout은 그 성질을 **일부러 이용하는** 기법이다. 모델 서빙에서 불확실성 추정 얘기가 나올 때 다시 만나게 된다.

## 오늘의 정리

1. Dropout이 뉴런을 끄는 목적은 **공동적응을 깨는 것**이다. 뉴런들이 서로에게 의존해 조를 짜지 못하게 만든다.
2. 뉴런을 끄면 **가중합의 항 자체가 사라져서** 다음 층에 들어가는 값이 통째로 줄어든다. 끈 것만 0이 되고 끝나는 문제가 아니다.
3. `/(1-p)`는 "전부 켜져 있었다면 나왔을 값"을 추정하는 보정 계수다. 값을 키우는 게 목적이 아니라 **학습과 추론의 스케일을 일치시키는 것**이 목적이며, 추론 쪽에서 줄여도 결과는 같다. 학습 쪽에서 키우는 이유는 추론 코드를 가볍게 하려는 실무적 선택이다.
4. 보정은 **기댓값만** 맞춘다. 분산은 안 맞으므로 BatchNorm과 조합할 때 주의.
5. BatchNorm과 LayerNorm의 수식은 같고, **평균을 내는 축만 다르다**.
6. `model.eval()`은 Dropout과 BatchNorm 둘 다에 영향을 준다. 빼먹으면 조용히 틀린다.
